# Hantek Studio 0.2 controls expansion — 11 September 2026

The owner requested full ordinary scope control while working remotely tonight,
with tests requiring physical access deferred until tomorrow. Work stayed in
this repository. No driver, Windows security, firmware, calibration, reset,
instrument filesystem, DUT or CNC capability was changed.

## Delivered behavior

React/Electron now has a Controls view with the scope image, F1–F5, channel,
horizontal, trigger, acquisition, measurement, cursor, display and math controls.
The shared catalog has 39 named gestures. Nine have a specific screen-observed
result below; 30 remain bench-pending. Existing Run/Stop and captures remain.

The Python CLI and JSON adapter expose the same controls, plus offline capability
listing and a raw settings record. There is no generic key/command passthrough
or absolute numeric setter. One button press or 1–5 rotary steps are accepted.
Each step is logged before sending, has one bounded reply/echo exchange and is
never retried. A completed exchange still leaves execution unverified until its
display is inspected. The desktop attempts a new preview after each gesture.

Previous images stay visibly invalidated after requests, failures, disconnects
and while reconnecting. Only a fresh returned capture clears that state. A null
post-command preview appears as an unconfirmed/error result. Demo captures,
gesture logs and settings records are labelled simulated and never open USB.

## Issues found and handled

The first echo met a pending short status response. A deliberate bounded
read-only receive cleanup retained 40 bytes (the previous echo reply and a
known status), reached USB idle and was followed by a successful echo. Evidence:
`.local/desktop-diagnostics/control-preflight-drain-20260911T161641.917121Z.*`.
No automatic recovery was added.

The first CH1 scale gesture returned the documented one-byte `0x93` menu ID `05`
but its immediate following echo timed out. A separate valid screenshot showed
that the knob action had nevertheless changed the scope. The failed command
log remains failed with sent=1, acknowledged=1, completed=0. This confirmed why
requests must not be blindly retried.

The implementation now waits 200 ms after the key acknowledgement and rechecks
the deadline before its single echo. Subsequent tested gestures completed both
reply and echo. The original source implementations also space their writes.
This is an observed timing improvement, not a guarantee for every firmware.

Two screenshots after the second CH1 coupling gesture failed the whole-image
checksum. Offline analysis found complete responses, exactly 768000 pixel bytes,
valid individual frames and no buffered/trailing bytes. Expected/computed sums
were 0x79/0x22 and 0x20/0x24. All failed data remains under
`ch1-coupling-gnd-screen/` and `ch1-coupling-gnd-screen-recheck/`. The analysis is
`.local/desktop-diagnostics/coupling-ground-checksum-analysis.json`. Cause remains
unresolved; integrity checks were preserved. The deliberate recheck sent only a
screenshot, not another setting change.

Review also found and fixed a missing Node bridge action allowlist extension,
a demo settings button that did not save its record, and stale-preview handling
after a command or reconnect. Regression checks exercise all three paths.

real Node-to-Python offline catalog request. UI checks cover the existing
workspace/library (14), new Controls view (10) and mocked failure/reconnect

Single/Force/Autoset with a known signal, Acquire/Measure/Cursor/Display/Math/FFT

remain pending rather than being inferred from demo tests.

Numeric SYSData decoding, absolute settings, preset restoration and waveform
export require additional implementation and firmware validation. They are
not presented as available merely because the front panel is controllable.
