# Desktop app session — 11 September 2026

## Objective

Add a standalone Windows React/Electron app, Hantek Studio, to the established
DSO5102P repository while preserving the command-line tools used by AI agents.
The package includes its Python runtime so normal desktop users do not need a
separate Python installation. The existing Microsoft WinUSB binding remains
the hardware connection; no driver or Windows security change is part of this
desktop implementation.

## Implemented scope

- USB and clearly labelled demo workspaces, with an explicit connection step.
- Screenshot capture and bounded successive screen previews.
- Explicit acquisition Run/Stop requests, operation logging and a following
  screen preview for the operator to inspect. Displayed state remains unverified
  until actually checked; no automatic state-changing retry.
- A saved-capture library, titles, notes, PNG export and original-file access.
- Preferences for mode, storage directory, interface GUID and refresh interval.
- A narrow Electron-to-Python adapter limited to the five established actions.
- A Windows portable build and a complete unpacked-folder alternative.

Voltage range, timebase and trigger controls, raw waveform acquisition and
numeric signal analysis are not included. The app has no AI chat, API-key
requirement, SSH endpoint or network service. AI agents retain the existing
repository launcher and CLI.

## Files and implementation boundaries

| Area | Purpose |
| --- | --- |
| `desktop/` | React UI, shared API, Electron host/service, tests and package configuration |
| `src/desktop_bridge.py` | One JSON request, strict validation, unchanged scope-client invocation and one JSON response |
| `tests/test_desktop_bridge.py` | Offline adapter validation and mocked client/device integration |
| `scripts/build-desktop.ps1` | Locked dependency install, private Python bundle, checks and Windows packaging |
| `scripts/start-desktop.ps1` | Launch the built portable app without installation |
| `docs/DESKTOP_APP.md` | User, build and developer instructions |

The existing `src/hantek_scope.py` and `scripts/scope.ps1` interfaces are preserved.
Only one app instance is intended to run. Each actual USB operation retains
exclusive access; automatic preview must be paused before handing the scope to
an external agent or CLI process.

Repository-local preferences and previews use `.local/desktop-profile/`; saved
hardware captures use `artifacts/captures/`, acquisition logs use
`artifacts/logs/`, and demo captures use `artifacts/demo/captures/`. Local state,
captures and build products remain ignored by Git. A package moved outside the
repository defaults to the user's application-data and Documents locations.

## Portable launch and a rejected frame

The final portable executable launched its own extracted app and found the
repository storage correctly. The first Connect action returned a screenshot
with a bulk-checksum mismatch. The app rejected it, disabled connected actions,
and kept the previously saved image explicitly marked as historical.

The failed preview was preserved separately from disposable previews at
`.local/desktop-diagnostics/failed-preview-24f586ba-cd4f-4ed5-a465-25def4798007/`.
Offline replay confirmed 78 individually valid frames, exactly 768000 pixel
bytes, and a fully consumed terminal with no trailing bytes. The instrument's
whole-image checksum was `0x2C`; the received pixels summed to `0x4D`.
The check was retained unchanged. No driver reinstall or automatic recovery
was performed. The cause of this individual inconsistent image is not established.

One explicit reconnect then succeeded with complete image data and verified
checksums. Its preserved evidence is
`.local/desktop-diagnostics/portable-success-scope-20260911T160129.542158Z/`.
The native window was inspected with the actual scope preview visible; Auto
acquisition, CH1 1.00 V/div and 800 us/div remained displayed. The portable app
was left open and connected with automatic preview off. No acquisition
commands were sent during this final launch check.

The final executable is 107299612 bytes. Its SHA-256 and build timestamp are
saved in `.local/desktop-release-manifest.json`; the source can reproduce the
package using the documented build script.
